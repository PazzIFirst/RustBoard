# 方案：M2 面板（v0.2.0）

> 目标里程碑：M2 面板　｜　对应 [requirements.md](../requirements.md) §12 M2
> 验收：浏览器里能看到四类曲线并自由缩放；改采样间隔 1 分钟内生效；面板登录可用。
> 依赖：证书轮换阶段先合入（都要改 `rustboard-hub/src/main.rs`），本方案按文件边界顺序执行。

## 1. 目标与验收标准

| # | 验收标准 | 验证方式 |
|---|---|---|
| M2-1 | `web/` 为 React + TS + Vite 工程，`pnpm build` 与 `tsc --noEmit` 通过 | CI web job |
| M2-2 | 浏览器可登录面板（单管理员 + Argon2id），错误密码限速，登出可用 | e2e + 单测 |
| M2-3 | 概览页展示每台机器状态、CPU/内存/磁盘最新值、采样间隔 | e2e API + 构建产物 |
| M2-4 | 单机详情页四类曲线：CPU、内存、磁盘（按挂载点）、网卡上下行速率；支持 1h/6h/24h/7d/自定义范围与拖拽缩放 | 前端构建 + API e2e |
| M2-5 | 服务端按时间跨度自动降采样（≤2000 点/曲线），一次查询多指标 | 单测 + e2e 断言 `bucket_ms` 与点数 |
| M2-6 | 修改采样间隔后 ≤60s 生效（hub 落库 + 踢会话重连 + Welcome 下发） | e2e 观察 agent 日志 |
| M2-7 | 管理 API 必须携带 Bearer token；面板 token 只在服务端使用，不下发浏览器 | 单测 + e2e 401/200 |
| M2-8 | 静态资源由面板进程提供，SPA 路由回退 `index.html`；`/api/*` 不参与回退 | 单测 + curl |

**非目标**（留给 M3/M4/M5）：TOTP、多用户、scoped 只读 token、面板 HTTPS、告警、计数器 epoch 结转、1m/1h 物化降采样表、真正内嵌前端资源（用 feature 预留，M5 打包启用）、浏览器自动化测试。

> 面板 → hub 的客户端在 M2 只支持 `http://`（同机回环 / VPN 内网）；`https://` hub 由 M5 的
> 反代或组网方案承接。reqwest 已按 `default-features = false` 引入，后续开 TLS feature 即可。

## 3. 接口契约（前端 / 面板 / hub 三方冻结）

### 3.1 hub 管理 API（`admin_listen`）

除 `GET /healthz` 外全部要求 `Authorization: Bearer <admin_token>`，失败 `401` + JSON `{"error":"unauthorized"}`。
token 比较用常量时间；`admin_token` 为空时 hub 启动失败并提示运行 `rustboard-hub admin-token`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/healthz` | 免鉴权，`ok` |
| GET | `/api/v1/system` | 版本、协议、服务端证书指纹/到期时间 |
| GET | `/api/v1/overview?window_ms=` | agents + 最新关键指标 + 各机采样间隔 |
| GET | `/api/v1/agents` | 原列表，保留 |
| GET | `/api/v1/agents/{id}/latest?window_ms=` | 该机每序列最新一点 |
| GET | `/api/v1/agents/{id}/series?metric=..&metric=..&from=&to=&bucket_ms=` | 多指标、服务端聚合 |
| GET | `/api/v1/agents/{id}/settings` | `{agent_id, sample_interval_ms}` |
| PUT | `/api/v1/agents/{id}/settings` | `{sample_interval_ms}`，1000–300000 |

`overview` 响应：

```json
{ "server_time": 0, "agents": [AgentRecord],
  "latest": [{"agent_id":"","metric":"","labels":{},"ts":0,"value":0.0}],
  "settings": [{"agent_id":"","sample_interval_ms":5000}] }
```

`series` 响应（`bucket_ms` 必返，便于前端标注）：

```json
{ "bucket_ms": 60000,
  "series": [{"metric":"cpu.usage","labels":{},"points":[[1730000000000,12.3]]}] }
```

规则：`from < to`；跨度 ≤ 32 天；`metric` 1–20 个、每个 ≤64 字符且仅 `[a-z0-9_.-]`；
不传 `bucket_ms` 时按跨度自动选 `[1s,5s,10s,30s,1m,5m,15m,1h,6h]` 中使单曲线 ≤1500 点的最小档；
单次返回点数上限 20000、序列（metric+labels 组合）上限 50。超限返回 `400`。

`latest`：窗口默认 5 分钟（上限 1 小时），按 `(metric, labels)` 去重取最新点；
`overview.latest` 只查 `cpu.usage`、`mem.used`、`mem.total`、`disk.used`、`disk.total`、`load.1`、`uptime`，
窗口固定 60s，避免全表扫描。

### 3.2 面板 API（浏览器 → panel，同源）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | `{password}` → 204 + `Set-Cookie: rb_session=...`；401/429 |
| POST | `/api/logout` | 清会话与 Cookie |
| GET | `/api/session` | `{authenticated: bool}` |
| GET | `/api/overview` | 透传 hub |
| GET | `/api/agents/{id}/latest` | 透传 |
| GET | `/api/agents/{id}/series` | 透传 |
| GET/PUT | `/api/agents/{id}/settings` | 透传 |
| GET | `/api/system` | 透传 |

- Cookie：`HttpOnly; SameSite=Lax; Path=/`；请求头 `X-Forwarded-Proto: https` 时加 `Secure`；
  默认 12 小时，服务端内存会话表（重启需重新登录）。
- 登录限速：同一 IP 连续 5 次失败锁 15 分钟（内存表，返回 429）。
- 面板 → hub 的 Bearer token 只存在于面板配置，任何响应都不得回显；hub 401 时面板返回 502 `hub_auth_failed` 并记日志。
- 变更类请求要求 `Content-Type: application/json`；不实现 CORS（前后端同源）。

### 3.3 配置

`HubConfig`：

| 字段 | 默认 | 说明 |
|---|---|---|
| `admin_token` | 空 | `hub init` 随机生成；`hub admin-token` 可补生成/查看 |

`PanelConfig` 新增：

| 字段 | 默认 | 说明 |
|---|---|---|
| `admin_password_hash` | 空 | Argon2id PHC 字符串；`panel init` 生成 |
| `session_ttl_hours` | 12 | 会话有效期 |
| `static_dir` | 空 | 空则按 `web/dist` → `/usr/share/rustboard/web` 查找 |
| `token` | 已有 | hub 管理 token |

`panel init`：默认生成 20 字符随机密码并**只打印一次**；`--password` 可指定；`--hub` 缺省时尝试读
`/etc/rustboard/hub.toml` 的 `admin_listen` 与 `admin_token`，读不到则提示 `--hub-token`。

## 4. 存储与查询（`rustboard-core`）

Schema v4（纯新增表）：

```sql
CREATE TABLE IF NOT EXISTS agent_settings (
    agent_id          TEXT PRIMARY KEY,
    sample_interval_ms INTEGER NOT NULL,
    updated_at        INTEGER NOT NULL
);
```

`Storage` 新增方法：

```rust
fn get_sample_interval(&self, agent_id: &str) -> Result<Option<u64>>;
fn set_sample_interval(&self, agent_id: &str, ms: u64, now: i64) -> Result<()>;
fn list_sample_intervals(&self) -> Result<Vec<(String, u64)>>;
fn query_series_bucketed(&self, q: &SeriesQuery, bucket_ms: i64) -> Result<Vec<SeriesRow>>;
fn latest_samples(&self, since: i64, metrics: &[String], agent: Option<&str>) -> Result<Vec<SeriesRow>>;
```

- `query_series_bucketed`：`GROUP BY metric, labels, ts/bucket`，`AVG(value)`，`ts` 返回桶起点；参数全部绑定。
- `latest_samples`：先按窗口取行，Rust 侧按 `(agent_id, metric, labels)` 保留最大 `ts`；返回顺序稳定。
- `AgentRecord` 不变（避免动协议与既有 API 消费者）。

## 5. hub 行为

1. 鉴权中间件挂在 `/api/v1/*`；`/healthz` 单独放行。
2. `handle_session` 的 Welcome 使用 `get_sample_interval(agent_id)` 覆盖默认值：
   `u64::try_from(ms).unwrap_or(cfg.sample_interval_ms)`（读取失败记 warn 用默认）。
3. `PUT settings`：校验范围 → 落库 → `sessions.shutdown_reason(agent_id, Reconfigure)`；
   会话收到后发送 `Close(1000)` 正常退出，**不发 revoked Problem**。agent 1s 后重连，Welcome 带新间隔。
4. `SessionRegistry` 的取消信号从 `watch::Sender<bool>` 改为 `watch::Sender<ShutdownReason>`：
   `enum ShutdownReason { Revoke, Reconfigure }`；吊销轮询用 `Revoke`，配置变更用 `Reconfigure`，
   原有“最后一条连接才 offline”语义不变。
5. 管理 API 请求体上限 64 KiB，响应 `Cache-Control: no-store`。

## 6. agent 行为

- `run_async` 创建 `Arc<AtomicU64> interval`（初值 `cfg.sample_interval_ms`）。
- 采集循环：每轮结束读取当前值 `sleep(Duration::from_millis(ms))`；首轮立即采集。
  变为新值后最多延迟一个旧周期生效（默认 5s，满足 ≤60s）。
- `session()` 收到 Welcome：`interval.store(w.sample_interval_ms)` 并打日志
  `采样间隔已更新 ms=...`（e2e 依赖该行）。
- 0 值拒绝（沿用现有校验）。

## 7. 面板实现

- 模块：`auth.rs`（Argon2id、会话表、限速）、`proxy.rs`（reqwest 客户端 + 统一错误映射）、
  `web.rs`（静态资源 + SPA 回退）、`main.rs`（CLI/装配）。
- 静态资源：默认从 `static_dir`/`web/dist`/`/usr/share/rustboard/web` 读盘；
  feature `embedded-web`（`include_dir`）供 M5 打包时内嵌，本阶段 CI 只构建不启用。
- 找不到 `index.html` 时返回可读的 503 提示（而不是 panic）。
- MIME 只映射 `html/js/css/svg/png/ico/woff2/json`；路径拒绝 `..`、绝对路径、符号链接逃逸
  （`std::fs::canonicalize` 后必须仍在根目录内）。

## 8. 前端

```
/                → 未登录跳 /login；已登录概览
/login           → 密码登录
/agents/:id      → 详情：四类图表 + 范围选择 + 采样间隔
```

- 依赖：`react`、`react-dom`、`react-router-dom`、`uplot`；构建 `vite` + `typescript`。
- 图表封装 `components/Chart.tsx`：`uPlot` 实例 + `ResizeObserver` + 卸载销毁；
  拖拽选择区域即缩放，双击/按钮恢复全范围；空数据与错误态不渲染空白坐标轴。
- 数据：概览 30s 轮询；详情切换范围/缩放时重新请求；请求带 `AbortController` 取消过期请求。
- CPU：`cpu.usage`、`cpu.iowait`；内存：`mem.used`、`mem.total`、`swap.used`（同一 MiB 轴）；
  磁盘：按 `labels.mount` 计算 `disk.used/disk.total` 百分比，多挂载点多条线；
  网络：`net.rx_bytes`/`net.tx_bytes` 用相邻点差计算速率（负值/epoch 跳变按 0 处理），
  另用最新值展示每网卡累计上下行字节数。
- 无任何密钥进入前端 bundle；`api.ts` 只调用面板 `/api/*`。

## 10. 兼容性结论

| 场景 | 结论 |
|---|---|
| 已安装 v0.1 agent | 连接不受影响；Welcome 间隔被忽略（仍按本地配置），面板改间隔对旧 agent 不生效，需升级 |
| 已安装 v0.1 hub 配置 | 缺 `admin_token` → 启动失败并给出修复命令；这是有意的安全默认 |
| 既有 SQLite | v3→v4 只建新表，不重写旧行；回滚后旧版本可忽略该表 |
| 协议 | 不新增帧，`PROTOCOL_VERSION` 不变 |
| 面板占位页 | 被新前端替换；`/healthz` 保持 |

## 11. 测试点清单

单测：
- hub：Bearer 校验（缺失/错误/正确、常量时间路径）、token 为空拒绝启动、series 参数边界、
  自动 bucket 档位、overview latest 去重、settings 范围校验、`Reconfigure` 关闭语义；
- storage：v4 迁移幂等、settings 读写、bucket 聚合（同桶多点的 avg、空桶不补点）、latest 去重；
- panel：Argon2id 验证、会话过期/清理、登录限速、Cookie 属性、静态路径穿越拒绝、SPA 回退、代理错误映射；
- agent：Welcome 间隔写入 atomic、0 值拒绝；
- 前端：`format.ts`/`rate.ts` 纯函数（负值、重置、空数组）。

e2e（`tests/e2e/panel.sh`）：
1. hub init → 启动，带 token 访问 `/api/v1/agents` 200；不带 token 401；
2. panel init（固定密码）→ 启动；错误密码 401、5 次后 429；正确密码拿 Cookie；
3. 通过面板改 interval=10s → 60s 内 agent 日志出现 `采样间隔已更新 ms=10000`；
4. series 查询多指标返回 `bucket_ms` 与 ≤2000 点；
5. 无 Cookie 访问 `/api/overview` 401；`/` 返回 HTML；`/agents/x` 回退 HTML。

## 12. 回滚方式

- 数据库 v4 只增表，回滚代码后旧版本忽略；
- `admin_token` 鉴权回滚即恢复无鉴权（不安全），只在紧急时使用；
- 前端为新增目录，回滚到占位页即可；
- 采样间隔功能回滚后 agent 仍使用配置值，无数据损坏。

## 13. 执行顺序（文件独占）

1. 证书阶段先合入并打 checkpoint（占用 hub `main.rs` / agent `main.rs`）；
2. 本阶段启动后：
   - `web/**` + `crates/rustboard-panel/**`（A 线，与证书阶段无文件重叠，可并行）；
   - hub/agent/storage 改造（B 线，等证书阶段合并后再开始）；
3. 两条线都完成后统一门禁、评审、渗透，再打 `checkpoint/2026-10-23-m2-panel` 与 `v0.2.0`。
