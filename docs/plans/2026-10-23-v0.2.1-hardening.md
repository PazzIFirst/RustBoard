# v0.2.1 已知问题硬化方案

> 关联：[known-issues.md](../known-issues.md) KI-01 ~ KI-12；[status.md](../status.md) 已知限制 5–9。
> 基线：`main@170e48e`（v0.2.0）。不改变协议版本，不改变现有表结构。

## 1. 目标与验收

在不引入新功能的前提下，修掉 v0.2.0 遗留的中危/低危问题，并补上独立回归。

总体验收：

- 单 IP 洪水连接不能挤掉已建立会话；断开后计数归零。
- 长查询执行期间，写入与心跳刷新不被全局锁阻塞。
- 反代场景下伪造 `X-Forwarded-*` 不影响限速键与 Cookie 安全属性。
- 管理 API 有每 IP 限速；弱 token 拒绝启动；未知 API 先鉴权。
- 运行中 `rotate-cert` 在 15s 内热生效；并发 rotate 被文件锁拒绝。
- `session_max_hours=0` 的会话仍会周期性检查客户端证书。
- 面板可重置密码；变更请求有 Origin 校验。
- `cargo fmt/clippy/test`、三套旧 e2e、新增 e2e 全绿。

## 3. 接口与数据变更

### 3.1 配置新增（全部有默认值，旧配置可直接启动）

```toml
# hub.toml
max_connections_per_ip = 16        # 1–256，单来源 IP 并发连接上限
admin_rate_limit_per_min = 60      # 0 表示关闭；1–6000
admin_write_rate_limit_per_min = 10
admin_token 仍为字符串；新增强度校验（长度 + 字符集 + 不同字符数）

# agent.toml
cert_check_interval_hours = 6      # 1–168；0 不允许
session_max_hours = 0              # 保留「不主动重连」语义，但不再跳过周期检查

# panel.toml
trusted_proxies = []               # 精确 IP 或 CIDR，仅这些来源的 XFF/XFP 可信
cookie_secure = "auto"             # auto | always | never
public_origin = ""                 # 可选，例如 https://panel.example.com；Origin 校验用
```

### 3.2 API / 行为变化

| 变化 | 兼容性 |
|---|---|
| `/api/v1/*` 增加每 IP 60 req/min 限速，超限 429 + `Retry-After` | 正常面板/脚本远低于阈值；新增响应码 |
| 未知 `/api/v1/*` 先 Bearer 再 404 | 无 token 从 404 变 401，符合预期 |
| `GET /api/v1/system` 的 `cert` 增加 `live` 与 `disk` 子对象 | 旧字段保留，面板忽略新增字段 |
| `rustboard-panel reset-password` 新子命令 | 纯新增 |
| `rotate-cert` 增加锁文件与 15s 热加载 | 输出提示变化 |
| `panel` 配置新增可信代理 | 默认值保持现状（只信直连 IP） |

`/api/v1/system` 目标结构：

```json
{
  "version": "0.2.1",
  "protocol": 2,
  "server_time": 0,
  "cert": {
    "fingerprint": "<live>",
    "not_after": 0,
    "days_left": 0,
    "live": { "fingerprint": "...", "not_after": 0, "days_left": 0 },
    "disk": { "fingerprint": "...", "not_after": 0, "days_left": 0 }
  }
}
```

顶层 `fingerprint/not_after/days_left` 继续等于 live，避免旧面板显示错乱。

### 3.3 存储

**不改 schema**。SQLite 连接池只是打开多条连接：

- 写连接：1 条，保持 `journal_mode=WAL`、事务、busy_timeout。
- 读连接：默认 4 条（`read_pool_size` 可配置 1–16），`PRAGMA query_only=ON`。
- 内存库用 `file:rustboard-<pid>-<seq>?mode=memory&cache=shared`，保证多连接同库。
- 所有现有 `Storage` trait 方法签名不变。

## 4. 各问题实现要点

### KI-01 连接限流

- 在 `serve_tls` 外增加 `ConnectionGuard`：
  - `global_preauth: Semaphore`，容量 `max(1, max_connections / 2)`；
  - `per_ip: Mutex<HashMap<IpAddr, usize>>`，容量 `max_connections_per_ip`。
- accept 后先尝试 per-IP，再尝试 global preauth；任一失败立即 `drop(tcp)` 并计数。
- TLS 握手成功、进入 HTTP 服务前释放 global preauth；per-IP 计数持有到连接结束。
- 这样已认证会话不会被未认证洪水挤掉，单 IP 最多占 16 条。
- 超时：`TLS_HANDSHAKE_TIMEOUT` 与 `HEADER_READ_TIMEOUT` 改为 5s。
- per-IP 表在计数归零时删除键；超过 4096 个来源时清理为 0 的项。

### KI-02 SQLite 读写分离

- `SqliteStorage` 字段改为 `writer: Mutex<Connection>`、`readers: Vec<Mutex<Connection>>`、`next_reader: AtomicUsize`。
- `lock_write()` / `lock_read()`；读方法一律 `lock_read`。
- 打开顺序：writer 建库/迁移 → readers 打开同一路径并设置 `query_only`。
- 读连接打开失败时回退为 1 条（记录 WARN），不允许启动失败。
- 新增 `open_with_readers(path, n)` 供测试；`open` 使用默认 4。
- 测试：临时文件库建大表，开一个读事务/长查询，另一个线程 `insert_batch` 在 200ms 内完成。

### KI-03 可信反代

- 新增 `panel::auth::client_ip(peer, headers, trusted_proxies)`：
  - `trusted_proxies` 支持精确 IP 与 CIDR（IPv4/IPv6），启动时解析校验；
  - 从 XFF 右侧向左跳过可信代理，取第一个非可信地址；
  - XFF 非法（非 IP、超过 8 跳）回退直连 IP；
  - 直连对端不在可信列表时完全忽略 XFF。
- `api_login` / `api_logout` 使用该函数；限速键用返回 IP。
- `cookie_secure`：
  - `always` → true；`never` → false；
  - `auto` → 仅当直连对端可信且 XFP=https 时 true。
- 新增 `public_origin`；Origin 校验见 KI-07。

### KI-04 token 强度

- `admin_token_is_strong`：
  - 长度 ≥ 32；
  - 仅 ASCII 可见字符（0x21–0x7e）；
  - 至少 16 个不同字符；
  - 不在占位符黑名单（大小写不敏感）：`changeme`、`change-me`、`secret`、`password`、`admin`、`token`、`rustboard`、`00000000`、`aaaaaaaa`。
- 错误信息点明失败原因，不打印 token。

### KI-05 管理 API 限速

- `AdminRateLimiter`：`Mutex<HashMap<IpAddr, Window>>`，固定 60s 窗口。
- 读接口 60/min；`PUT /settings` 与后续 M3 控制写接口 10/min。
- 在 `admin_router` 的 Bearer 之后、handler 之前执行；`/healthz` 不经过。
- 超限返回 429 `{"error":"rate_limited"}` + `Retry-After: <秒>`；`no-store` 保留。
- 表容量 4096，满时清理过期窗口；窗口边界用注入时钟单测。
- 需要 `ConnectInfo<SocketAddr>`；`serve` 改为 `into_make_service_with_connect_info`。

### KI-06 非回环告警

- `warn_non_loopback_admin(addr)` 解析 `SocketAddr`（非法地址启动失败，与 bind 一致）。
- 非 loopback 打 WARN，包含「明文 HTTP」「只应置于 VPN/可信反代后」。
- 回环不打；agent 入口保持 INFO。

### KI-07 Origin/CSRF

- 中间件 `same_origin_guard` 只拦截 `POST/PUT/PATCH/DELETE` 的 `/api/*`：
  - 有 `Origin`：必须是 `http(s)://<Host>` 或 `public_origin` 的 scheme+host+port 完全一致；
  - 无 `Origin`：要求 `Content-Type: application/json`（现有 login/logout/settings 已满足）；
  - 不合法返回 403 `{"error":"origin_mismatch"}`。
- `public_origin` 为空时只接受同 Host；反代改 Host 的场景由运维显式配置。
- 单测覆盖：同源、跨源、子域、端口不同、无 Origin + JSON、无 Origin + 表单。

### KI-08 未知 API 鉴权

- 受保护路由树增加：
  - `.route("/api/v1", any(api_not_found))`
  - `.route("/api/v1/{*rest}", any(api_not_found))`
- 兜底 handler 返回 404 `{"error":"not_found"}`，但已过 Bearer。
- 保留现有具体路由优先级。

### KI-09 面板密码重置

- `panel` CLI 增加 `ResetPassword { config, password: Option<String>, generate: bool }`：
  - 未传 `--password` 时生成 20 位随机密码；
  - 写回 `admin_password_hash`，文件 0600；
  - stdout 只打印新密码一次与提示。
- `init` 输出补充 `reset-password` 提示。
- e2e：重置后旧密码 401、新密码 204。

### KI-10 证书热加载与 live/disk

- `cert_rotation` 新增：
  - `spawn_cert_file_watcher(cfg, tls_tx, live: Arc<RwLock<CertStatus>>)`：每 10s 读 server.crt/key，校验配套、CA 链、SAN；指纹变化才构建新 `ServerConfig` 并 `tls_tx.send`；
  - 加载失败保留旧配置并 WARN（每分钟最多一条）；
  - 初始 `live` 由启动加载写入。
- `AppState` 增加 `live_cert: Arc<RwLock<CertStatus>>`；`system_info` 同时读 live 与 disk。
- `rotate-cert` 输出「运行中 hub 将在 ≤10s 内自动加载」。
- e2e：运行中 rotate，轮询 `/api/v1/system` 直到 live 指纹 == disk，且新 TLS 连接证书指纹一致（≤15s）。

### KI-11 rotate 文件锁

- `CertLock`：`<cert_dir>/.rotate.lock`，`create_new` + 0600，内容 pid/time。
- 已存在：读 mtime；超过 10 分钟删除并重试一次；否则报错「另一个 rotate-cert 正在运行」。
- RAII Drop 删除；`rotate_cert` 全程持锁。
- 单测：先占锁再调用失败；删除后可成功；陈旧锁可恢复。

### KI-12 周期证书检查

- `cert_check_interval_hours`（默认 6，1–168）加入 `AgentConfig`。
- 会话空闲分支增加 `cert_timer`；到点时若 `days_left <= renew_before_days` 调用现有 `maybe_renew_client_cert`。
- 只在无在途批次时触发，避免与 ACK 等待争抢同一 stream。
- 定时器用 `MissedTickBehavior::Skip`；失败只 WARN。
- 单测：`cert_check_due(days_left, threshold, now, last)` 纯函数边界。

## 5. 兼容性

- 协议版本保持 2；无帧变更。
- 数据库 schema 保持 4；连接池对旧库透明。
- 配置项全部 `#[serde(default)]`；v0.2.0 配置可直接启动。
- `admin_token` 强度校验可能拒绝极弱旧 token：错误信息给出 `admin-token` 重新生成指引；这是有意的安全收紧。
- `cookie_secure=auto` 保持旧行为；只有显式 `always` 或可信反代才加 Secure。
- `rotate-cert` 加锁只影响并发调用；单进程行为不变。

4. agent 单测：周期检查纯函数、配置范围。
5. `tests/e2e/hardening.sh`（新建）：
   - 单 IP 空连接洪水后合法 agent 仍在线；
   - 反代伪造 XFF 不改变锁 IP；可信 XFF 分别计数；
   - 无 token 未知 API 401、带 token 404；
   - 第 61 次管理 API 请求 429；
   - 弱 token 启动失败；
   - rotate 热加载 ≤15s；
   - panel reset-password 旧密码失效。
6. 旧三套 e2e 全量重跑。

## 7. 回滚

- 代码回滚到 `170e48e` 即可；无 schema 变更、无协议变更。
- 配置新增字段删除后走默认值；`admin_token` 若被新校验拒绝，可临时回滚二进制或重新生成 token。
- 证书热加载失败不会替换旧配置，回滚只需停掉文件轮询（旧二进制无此任务）。
