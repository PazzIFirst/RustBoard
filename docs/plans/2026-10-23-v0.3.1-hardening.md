# v0.3.1 安全与可靠性硬化方案

> 基线：`main@cb6a3b6`（v0.3.0 发布后）。关联：
> [known-issues.md](../known-issues.md)、[status.md](../status.md)、
> GitHub Issues #9–#14。
>
> 目标：在不改协议版本、不改数据库 schema 的前提下，修掉 v0.3.0 遗留的中危与
> P1/P2 可靠性问题，并逐条对账 GitHub Issue。完成后发布 `v0.3.1`。

## 1. 目标与验收

1. 管理 API / 面板的慢速连接不能长期占用 fd；洪水下健康请求仍可用。
2. Agent 本地缓冲的**物理文件**有硬上界；淘汰后的偏移持久化，重启不复活已淘汰数据。
3. Agent 所有 WebSocket 写操作有独立超时；`session_max_hours=0` 也能从半死连接恢复。
4. 服务端证书仅因过期（CA/密钥/SAN 均合法）时，hub 启动能自动重签，不再要求人工 `rotate-cert`。
5. 旧会话清理与新会话注册的竞态不会把 `online` 覆盖成 `offline`。
6. 对 GitHub #9/#11 给出可复现的验证证据，明确关闭或剩余范围。
7. `cargo fmt/clippy/test`、五套 e2e、`cargo audit`、CI 全绿后打 `v0.3.1`。

## 3. 详细方案

### 3.1 KI-17：管理 API / 面板慢速连接（中危）

**现状**：hub agent 入口已有 TLS/header 超时与 per-IP 限制；hub 管理口和面板仍直接
`axum::serve`，没有 header 读超时、全局/每 IP 连接上限。

**实现**：
- 新增共享的纯 HTTP accept 层（可分别放在 hub/panel 内部，逻辑一致）：
  - `header_read_timeout = 5s`；
  - `max_connections = 256`、`max_connections_per_ip = 32`（常量，后续可配置）；
  - accept 后先占 per-IP 许可，再占全局许可；拿不到立即关闭 TCP；
  - 计数归零删除 key，表容量上限 4096；
  - 每条连接用 `hyper::server::conn::http1::Builder` + `TokioIo` + `TowerToHyperService`，
    与 hub agent TLS 入口同款，避免 `axum::serve` 无超时。
- 只监听回环时仍启用（防本机低权用户/容器内异常进程）。
- 日志只记录来源 IP 与计数，不记录请求头。

**验收**：
- 30 条只发一半 header 的 TCP，10s 内全部被关闭；`/healthz` 仍 200。
- 单 IP 连接数达到上限后新连接被立即关闭，其他 IP 不受影响。
- 面板与 hub 管理口都有对应 e2e。

### 3.2 #10：DiskBuffer 容量硬上界与恢复

**现状**：`enforce_limit()` 只推进内存 `read_offset`，不 `save_meta()`；只有
`pending.is_empty()` 才 `compact()`；`recover()` 后不重新限额。物理日志可持续增长，
重启后旧记录复活。

**实现**：
1. 淘汰路径（字节或时间上限）只要推进了 `read_offset`，立即 `save_meta()`（原子写）。
2. 增加压实水位：`buffer.log` 物理长度 > `max(2 * max_bytes, max_bytes + 1MiB)` 时，
   即使仍有 pending 也 `compact()`；压实后重置读写偏移并持久化。
3. `recover()` 扫描完成后调用统一的 `enforce_limit(now)`，保证：
   - `pending_bytes <= max_bytes`；
   - 超过 `max_age` 的记录全部淘汰；
   - 已推进的 `read_offset` 在重启后仍生效。
4. 单条记录大于 `max_bytes` 时明确策略：保留该条但立即压实，后续新记录被淘汰；
   不 panic、不无限增长。
5. `buffer.meta` 格式不变（向后兼容）；旧文件首次打开时自动走一次限额/压实。

**测试**：
- 离线持续 push 超过上限：断言 `buffer.log` 长度有上界、`pending_bytes <= max_bytes`。
- 淘汰后立即 drop/open：旧记录不复活，`pending_bytes <= max_bytes`。
- 淘汰后 ack：压实前后偏移与后续读取/ACK 一致。
- `max_age_ms = 0`、单条超大记录、meta 写入失败/崩溃窗口。
- 现有 DiskBuffer 幂等/恢复测试全部保持。

### 3.3 #12：Agent WebSocket 写超时

**实现**：
- `AgentConfig` 新增 `send_timeout_secs`（默认 15，范围 1–120，serde default）。
- 新增 `send_frame_with_timeout(sink, frame, timeout)` / `send_message_with_timeout`，
  对 `SinkExt::send` 包 `tokio::time::timeout`；超时返回可重试错误。
- 覆盖所有写路径：Hello、Batch、Ack 等待期间的 Pong、心跳 Ping、续签 CSR、
  `renew` 子命令的帧。
- ACK 20s 计时保持在发送成功之后；发送超时与会话重连退避衔接。
- 日志只记录“发送超时”和帧类型，不打印帧内容。

**测试**：
- 自定义 `Sink`：`poll_ready`/`poll_flush` 永不就绪，`send_frame_with_timeout` 在超时内返回错误。
- 假 WS 服务端完成 Welcome 后停止读取，`session_max_hours=0` 时 agent 在发送超时内退出。
- 正常慢速但持续读取不被误杀；服务端不 ACK 仍走原 20s ACK 超时。

### 3.4 #13：证书过期启动自愈

**实现**：
- `load_or_repair_tls_config()` 分类：
  1. CA 材料非法 / 不配套：拒绝启动（不变）；
  2. server key/cert 缺失或不配套：用 CA 重签（现有行为）；
  3. key/cert 配套、CA 链和 SAN 合法，仅 `notAfter <= now`：持 `CertLock` 用当前 CA
     重签，成对备份，校验新证书后再构建 TLS 配置；
  4. 其他（不可解析 / 非本 CA 签发 / SAN 不覆盖）：拒绝启动（不变）。
- 不静默替换 CA；不修改 `server_names`。
- 重签失败保留旧文件并拒绝启动，错误信息提示 `rotate-cert --force`。
- 与自动续签共用 `renew_server_cert_files` + 锁，避免并发写。

**测试**：
- 生成“当前 CA 签发、私钥配套、SAN 正确、已过期”的证书，`run` 能启动；
  新证书未过期、同一 CA、备份成对、权限正确。
- 未过期且不在阈值内：不重签、不改指纹。
- CA 不配套 / 不可解析 / SAN 缺失 / 私钥不匹配：仍启动失败且不写证书。
- e2e：过期证书启动后原 agent 用原 CA 重连，无需重新纳管。

### 3.5 #14：会话清理与在线状态竞态

**实现（推荐）**：
- `SessionRegistry` 增加 `unregister_last_and_mark(agent_id, conn_id, || -> Result<()>)`：
  - 持有注册表锁；
  - 删除 conn_id 后，如果仍有连接，直接返回“无需 offline”；
  - 如果没有连接，在锁内执行回调（写 `offline`/`revoked`/`has_active` 判断）；
  - 新连接的 `register` 必须等锁释放，因此不会插入“检查后、写 offline 前”的窗口。
- 回调只做单行状态更新（SQLite 已参数化、短事务），不持有注册表锁做网络/文件 IO。
- `SessionCleanup` 改为调用该原子方法；revoked 优先逻辑保持不变。
- 若回调失败，释放锁并记录错误，不清空其他连接。

**测试**：
- 确定性交错：旧连接注销进入临界区 → 新连接 register 阻塞 → offline 写入后新连接
  online；最终数据库 online。
- 反向：新连接先注册，旧清理看到活跃连接，不写 offline。
- 最后一条连接断开：合理时间内 offline。
- 高频注册/注销压力；revoked 始终最高优先级；#7 的旧 conn_id 语义不回归。

### 3.6 #9 / #11 对账验证

- #9：用 hardening/security e2e 复验：
  - 无/错 Bearer → 401，响应不含数据；
  - 正确 Bearer → 200；
  - 空 token 启动失败；
  - 未知 `/api/v1/*` 先 401 再 404；
  - 非回环管理监听有 WARN。
  - 在 Issue 评论中给出证据，并说明 scoped token、管理端 TLS 属 v1 范围外，
    保留 Issue 或拆新 Issue，不虚假关闭。
- #11：用 hardening 7.x 复验：
  - 可信反代不同 XFF 独立分桶；不可信来源伪造 XFF 无效；
  - 非法/超长/超 9 跳 XFF 返回 400；
  - 一个客户端锁定不影响另一个。
  - 评论 Issue 并建议关闭。

## 7. 回滚

- 代码回滚到 `cb6a3b6` 即可；无 schema/协议变更。
- `send_timeout_secs` 删除后走默认；旧 agent 配置不受影响。
- DiskBuffer 压实失败时保留原 `buffer.log`，不删除未确认记录；回滚后旧代码仍可读。
- 证书启动自愈若误判，保留成对备份；可 `rotate-cert --force` 或恢复备份。
- 会话清理原子化失败只影响状态显示，不影响数据入库；可回滚单文件。
