## 1. 目标与验收

1. **#9 scoped token**：管理 API 支持 read / write / admin 三级 token；只读 token
   不能执行控制或修改设置；token 可创建、列出、轮换、吊销；审计 actor 记录 token 名称；
   旧 `admin_token` 继续可用但标记为兼容路径。
2. **#9 管理端 TLS**：非回环管理监听必须启用 `admin_tls = "required"`，否则拒绝启动；
   Panel 支持 `https://` hub 地址和私有 CA（`hub_ca`）；远程 Panel 不再以明文 HTTP
   连接 hub。
3. **#17**：`agent revoke` 成功后，控制 API 和会话循环都不能再向该 agent 投递新命令；
   返回固定拒绝错误并记 `denied` 审计，不出现吊销后的成功审计。
4. **#20**：日志文件打开改为从根目录 fd 对完整绝对路径做一次 `openat2`，中间父目录
   被替换为符号链接时读取失败；不再存在“启动校验通过、运行期 dirfd 被重定向”的窗口。
   不启用 `RESOLVE_NO_XDEV`：独立 `/var`、tmpfs `/tmp`、bind mount 下的日志路径必须
   继续可用（实施期评审确认 `NO_XDEV` 会让 agent 因跨挂载日志而整体拒绝启动）。
5. **#21**：systemd 列表合并 `list-units` 与 `list-unit-files`，已安装但未加载、
   且通过白名单的 service 能出现在面板并执行 start；状态不伪造。
6. `cargo fmt/clippy/test`、`cargo audit`、既有 7 套 e2e、新增 `v033.sh`、CI 全绿后
   打 `v0.3.3`。

## 3. 现状与风险

- 管理 API 已有单一 Bearer `admin_token`、常量时间比较、每 IP 限速、未知路由先鉴权；
  **缺**按消费者分级、token 生命周期、非回环强制 TLS。
- Panel 只支持 `http://hub`，`hub_ca` 不存在；管理口非回环时只会 WARN，不会拒绝启动。

  能力/在线，不查 revoked；revoke 依赖 2s watcher。

  `O_NOFOLLOW` 只保护最后一个分量，中间父目录可被替换。
- systemd 只跑 `list-units --all`，已安装未加载的 unit 不可见。

## 4. 详细方案

### 4.1 #9：scoped token

#### 数据模型

SQLite schema 从 **v5 → v6**，只新增表，不改既有表：

```sql
CREATE TABLE IF NOT EXISTS api_tokens (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    name         TEXT NOT NULL UNIQUE,
    token_hash   TEXT NOT NULL UNIQUE,       -- SHA-256(hex)，不存明文
    scope        TEXT NOT NULL CHECK (scope IN ('read','write','admin')),
    created_at   INTEGER NOT NULL,
    last_used_at INTEGER,
    revoked_at   INTEGER
);
CREATE INDEX IF NOT EXISTS idx_api_tokens_hash ON api_tokens(token_hash);
```

- token 明文 = 32 字节随机数的 64 位 hex（复用 `new_secret()`），只在
  `token create` / `token rotate` 时输出一次；不写日志、不进审计。
- `scope` 是层级：`read < write < admin`；`write` 隐含读权限。
- `last_used_at` 在鉴权成功后 best-effort 更新；失败只记 debug，不影响请求。
- 吊销 = 写 `revoked_at`，不删除行，保留审计/排障信息。
- 旧 `admin_token` 不迁入表；作为 `admin` scope 的兼容路径保留。

#### CLI

```bash
rustboard-hub token create --config hub.toml --name panel-prod --scope write
rustboard-hub token list   --config hub.toml
rustboard-hub token rotate --config hub.toml --name panel-prod
rustboard-hub token revoke --config hub.toml --name old-panel
```

- `create`：name 1–64 字符、仅 `[a-zA-Z0-9._-]`；输出一次 token，重复 name 拒绝。
- `rotate`：同一行生成新 hash、清 `revoked_at`，输出一次新 token；旧 token 立即失效。
- `list`：只输出 name / scope / created_at / last_used_at / revoked_at，不含 hash/明文。
- `revoke`：不存在或已吊销返回明确错误；不删行。
- CLI 与运行中的 hub 通过 SQLite WAL 并发；鉴权中间件每次请求读库，能立即看到新/吊销。

#### 鉴权中间件

新增 `crates/rustboard-hub/src/auth.rs`：

```rust
#[derive(Clone, Copy, PartialEq, Eq)]
pub enum TokenScope { Read, Write, Admin }

#[derive(Clone)]
pub struct AuthPrincipal {
    pub name: String,
    pub scope: TokenScope,
    pub legacy: bool,
}

pub fn scope_allows(granted: TokenScope, required: TokenScope) -> bool;
pub async fn require_auth(...) -> Response; // 解析 Bearer -> 扩展插入 AuthPrincipal
```

- 先比较旧 `admin_token`（常量时间）；命中则 principal = `{name:"admin", scope:Admin,
  legacy:true}`，保持现有审计 actor。
- 否则 SHA-256 token，查 `api_tokens` 未吊销行；命中后更新 last_used；否则 401。
- 401 固定 `{"error":"unauthorized"}`，带 `WWW-Authenticate: Bearer`；不回显 token/内部错误。
- 401 不写审计（避免未认证请求打爆 DB），只 `tracing::warn` 记录来源 IP。
- 认证通过后，按路由要求检查 scope：
  - `read`：所有 GET `/api/v1/*`（agents/series/overview/latest/settings GET/control GET/audit/system）。
  - `write`：GET + `POST /agents/{id}/control` + `PUT /agents/{id}/settings`。
  - `admin`：全部，预留给未来 HTTP token 管理；本阶段 token CLI 不走 HTTP。
  - 只读 token 调写接口 → 403 `forbidden_scope`；已认证但无权限不写控制审计
    （请求尚未进入控制 handler），只记 warn。
- `/healthz` 保持免鉴权；未知 `/api/v1/*` 仍先认证，再 404，不泄露路由。
- Panel 的 `token` 字段可直接填 write scope token；浏览器仍不接触 token。

#### 审计 actor

- `AuditDraft::new` 改为接收 actor，或 `with_actor`；控制 handler 从
  `Extension<AuthPrincipal>` 取 token name。
- 旧 `admin_token` 保持 `actor="admin"`，既有 control e2e 6.10 不回归。
- 新 token 的 actor 是 token name（例如 `panel-prod`），不得包含 token 明文。

### 4.2 #9：管理端 TLS 与 Panel HTTPS

#### Hub 配置

新增：

```toml
admin_tls = "off"       # off | required，默认 off
```

- `off`：只允许 `admin_listen` 是回环地址（127.0.0.0/8、::1）；非回环启动失败，
  错误信息提示“改用 admin_tls=required 或只绑回环 + TLS 反代”。
- `required`：管理监听使用与 agent 入口相同的 `server.crt/server.key` 做 TLS
  （server-auth，不要求客户端证书）；新增 `tls::admin_server_config`
  （`with_no_client_auth` + TLS1.3 + ALPN http/1.1），**不能**复用要求客户端证书的
  `tls::server_config`。证书轮换沿用 mTLS 已校验的 `live_cert` 指纹（2s 轮询），
  运行中 rotate 后新连接自动使用新证书；构建失败保留旧配置。
- `server_names` 必须包含管理端访问名（IP/DNS）；否则启动失败并提示先更新
  `server_names` 再 `rotate-cert`（沿用现有证书规则）。
- `admin_tls=required` 时 `/healthz` 也走 HTTPS；日志明确 `管理 API 监听（HTTPS）`。
- 管理口继续使用现有 5s header / 10s body / 全局与每 IP 连接限制；TLS 握手超时 10s。
- `admin_tls=off` + 回环保持现有明文行为，兼容本地单机/反代同机部署。

#### Panel 配置与代理

新增：

```toml
hub_url = "https://127.0.0.1:8444"
hub_ca  = "/etc/rustboard/panel/hub-ca.crt"  # 可选；私有 CA 必填
```

- `ProxyClient::new(hub_url, token, hub_ca)`：
  - `http://` 只允许回环 host（127.0.0.0/8、::1、localhost）；非回环直接启动失败。
  - `https://` 允许；`hub_ca` 非空时读取 PEM（支持 bundle）并只信任该 CA
    （`tls_built_in_root_certs(false)`，系统根不叠加），为空则用系统根。
  - 保留 `no_proxy`、`redirect(Policy::none())`、30s 普通超时、70s 控制超时、
    8 MiB 响应上限；Bearer 仍只在服务端注入。
- `panel init` 仍写 `hub_url`；本阶段只支持配置字段，不新增交互式参数。
- 远程 Panel 必须用 `https://`；同机回环可继续 `http://127.0.0.1`。

#### 兼容性

- 旧配置默认 `admin_tls=off` + 回环 → 不变。
- 旧配置把 `admin_listen` 设为非回环且明文 → **v0.3.3 起拒绝启动**，这是有意的
  安全收紧；迁移方式：改 `admin_tls="required"` 或改回回环 + TLS 反代。
- 旧 Panel 远程 `http://hub` → 启动失败；改 `https://` + `hub_ca`。
- 管理证书复用 server.crt；若管理域名不在 SAN，先更新 `server_names` 并 `rotate-cert`。
- 旧 `admin_token` 仍可用，不强制迁移；新部署建议 `token create --scope write` 给 Panel。

### 4.3 #17：吊销窗口内拒绝控制命令

1. `hub/control.rs`：
   - 在 `control_action()` 读取能力前/后、投递前调用 `storage.is_revoked(&agent_id)`；
     命中返回 `Reject::revoked()`：HTTP 403、code `agent_revoked`、固定文案
     “agent 已被吊销”、`AUDIT_DENIED`。
   - 新增 `hub_codes::AGENT_REVOKED`，不与 `agent_offline` 混淆。
2. `hub/main.rs` 的 `SessionEvent::Control(command)`：
   - 在 `control.dispatch` 前用 `spawn_blocking` 调 `is_revoked`；命中则向
     `command.reply` 发送 `Err(ControlError::new(hub_codes::AGENT_REVOKED, ...))`，
     **不发送 ControlRequest**；会话继续等待 watcher 关闭。
   - 该检查是跨进程竞态的兜底；即使 revoke 恰好发生在 API 检查后，命令也不会到 agent。
3. 测试：
   - 单测：已吊销 agent 的 control_action 返回 403/agent_revoked/denied，fake agent
     未收到帧；未吊销正常。
   - 确定性并发：在会话 control 分支等待点暂停，先提交 revoke，再放行命令；断言
     mpsc 中的命令收到 agent_revoked 且 sink 无 ControlRequest。
   - 既有 #5 Batch 吊销、≤3s 连接关闭、重连拒绝测试保持。

### 4.4 #20：父路径 TOCTOU

把 `open_beneath(parent, file_name)` 改为单次完整路径解析：

```rust
fn open_log_path_absolute(path: &Path) -> io::Result<File>;
```

- 打开根目录：`open("/", O_RDONLY|O_DIRECTORY|O_CLOEXEC)`；
- 将配置的绝对路径去掉前导 `/`，对根 dirfd 调一次 `openat2`：
  - flags：`O_RDONLY|O_CLOEXEC|O_NOFOLLOW|O_NONBLOCK`
  - resolve：`RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS`
- **不启用 `RESOLVE_NO_XDEV`**（实施期评审修正）：v0.3.2 允许日志父目录位于独立挂载点
  （独立 `/var`、tmpfs `/tmp`、容器 bind mount）；`NO_XDEV` 会让 `validate_sources_io`
  在启动时 EXDEV，整个 agent 拒绝启动，与 §5“无配置兼容性变更”矛盾。跨挂载本身不是
  路径逃逸；单次 `openat2` + `NO_SYMLINKS|NO_MAGICLINKS|BENEATH` 已关闭父路径 TOCTOU。
- 这样每个父目录分量都在同一次 syscall 内解析，中间分量被替换为符号链接会被
  `RESOLVE_NO_SYMLINKS` 拒绝；不再先 `open(parent)` 再 `openat2(file_name)`。
- 保留：`fstat` 必须是普通文件；拒绝 FIFO/设备/目录；ENOSYS 不降级。
- 启动校验 `validate_sources_io` 使用同一 helper 打开并关闭，确保启动与运行策略一致；
  日志轮转/替换后每次 tail 重新安全打开。
- 测试：
  - 启动校验通过后，将中间父目录替换为指向 victim 目录的符号链接，调用 tail 必须失败，
    且不返回 victim sentinel；替换最终父目录/最终文件符号链接同样失败；
  - 多级中间目录、绝对/相对符号链接；**跨挂载点普通文件必须能正常读取**（兼容性回归）；
  - 正常文件、CRLF/大文件 tail 不回归；FIFO 仍快速拒绝。
- 不解决 KI-22（硬链接）；文档继续标注。

### 4.5 #21：systemd 已安装未加载 unit

`agent/control/systemd.rs`：

- 保留现有 `list-units --type=service --all ...`，新增
  `list-unit-files --type=service --no-legend --no-pager --plain`。
- 两次 exec 都使用既有 `exec::run` 与 `command_timeout_secs`；非零退出返回
  `control_failed`，不静默吞错。
- 解析 `list-unit-files` 每行 `unit state`（至少两列），只取 `.service`；
- 合并：
  - 以 unit 名为 key；`list-units` 记录优先（真实 load/active/sub/description）；

    `sub="dead"`、`description=""`；

- 排序：按 unit 名升序，稳定；面板显示逻辑不改。

  - 未加载 `demo.service` 出现在合并结果且状态为 not-loaded/inactive/dead；
  - 同时出现在两份输出时只出现一次且用 loaded 状态；
  - 非白名单/禁止 unit 仍过滤；`MAX_LIST_ITEMS` 截断；
  - 两次命令参数固定、无 shell；任一非零退出返回 control_failed；
  - 现有 action/list 测试全部保留。

## 5. 接口、配置与兼容性

| 变更 | 兼容性 |
|---|---|
| SQLite schema v6 `api_tokens` | 纯新增表；旧 v0.3.2 二进制忽略该表，可回滚；新二进制打开 v5 自动迁移 |
| `admin_tls = "off"\|"required"` | 默认 off；回环旧配置不变；非回环明文启动失败（有意收紧） |

| context `agent_revoked` | 新管理 API 错误码；协议 v2 不变，不影响 agent 帧 |
| #20/#21 | 无协议/配置/DB 变更 |
| 协议版本 / DB 版本 | 仍 v2 / **v6** |

升级顺序：

1. 先升级 hub 到 v0.3.3（迁移 DB，旧 token 继续有效）；
2. 配置 `admin_tls=required`（或保持回环 + 反代），必要时更新 `server_names` 并 rotate；
3. 创建 write scope token，更新 Panel `token`；
4. Panel 升级后使用 `https://` + `hub_ca`；
5. 最后吊销不再使用的旧 `admin_token`（本阶段仍保留兼容，不强制）。

### 6.2 e2e
