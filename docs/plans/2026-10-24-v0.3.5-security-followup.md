# v0.3.5 安全收口方案

> 基线：`main@9d021f8`（v0.3.4 发布后）。关联：`docs/known-issues.md` 的
> **KI-27（中危）**，以及 v0.3.4 评审留下的 **data_dir validate→create/chmod TOCTOU**
> 和两项低危/信息项。
>
> 目标：在进入 M4 告警与归档前，用一个短补丁关闭认证后单 IP 会话绕过和
> 数据目录路径竞态，**不新增功能、不改协议 / DB schema / 证书格式**。

1. 只实现本方案列出的 KI-27、data_dir 目录 fd 化、两项低风险告警；不改告警/归档、
   不改控制面白名单、不改 token 权限模型。

5. 方案提交后暂停，不修改业务代码；等用户压缩上下文并给出开工指示后，再创建
   `.worktrees/v035`。

## 1. 目标与验收

1. **KI-27**：同一来源 IP 的 WebSocket 会话数不超过 `max_connections_per_ip`；
   超限连接被拒绝（503/关闭），不能占满全局 `max_connections`，其他 agent 的重连/
   新纳管不受影响。TLS 层的全局 + per-IP 许可必须持有到 WebSocket 会话结束。
2. **data_dir TOCTOU**：从 `/` 到 data_dir 的目录创建与 `chmod` 使用目录 fd /
   `openat2`，不允许路径在校验后被替换为符号链接而作用到目标之外。
   - 任一祖先/最终组件为符号链接：拒绝；
   - 祖先或最终目录属于其他用户、或可被非特权用户写：拒绝（root 只接受 root
     拥有的目录；root 拥有的 sticky 目录如 `/tmp` 仅可作为可遍历祖先，最终目录仍须
     root 拥有）；
   - 默认 `/var/lib/rustboard/hub|agent` 和测试专用的 `/tmp/<unique>` 仍可用；
   - 已有 0755 数据目录在启动时收紧到 0700，已有 0644 DB/WAL/SHM 收紧到 0600。
3. **低风险项**：
   - `admin_auth_failure_limit_per_min = 0` 时，每窗口首条认证失败仍打 WARN（当前
     全部降为 DEBUG，关闭限速反而失去告警可见性）；
   - `database` 不在 `data_dir` 下（或为相对路径）时 hub 启动打一次 WARN，明确
     “父目录不收紧、DB 文件仍 0600”，不新增拒绝行为。
4. `cargo fmt/clippy/test`、`cargo audit`、既有 9 套 e2e、新增 `v035.sh`、CI 全绿后
   发布 `v0.3.5`；独立评审无 [严重]、渗透无高危。

## 3. 现状与风险

- **KI-27**：`serve_tls` 在 accept 后取得全局 `Semaphore` 许可和 `ConnectionLimiter`
  的 per-IP 许可；HTTP 升级为 WebSocket 后 `serve_connection` 返回，许可提前释放。
  `agent_ws` 只重新占全局 `session_slots`，没有 session 级 per-IP 许可。
  本地渗透：`max_connections_per_ip=16` 时单 IP 可建立 64 条 WS；小实例
  `max=8/per_ip=2` 时单 IP 占满 8 条，第 9 条合法连接 503。
- **data_dir TOCTOU**：v0.3.4 已做路径归一化、祖先/最终符号链接静态检查、
  共享/系统目录拒绝；但 `validate_private_dir_path` 与 `ensure_dir`/`set_permissions`
  之间仍是逐次路径解析。若 data_dir 位于他人可写祖先下，本地用户可在校验后替换
  为符号链接，使 root 的 chmod/创建作用到目标外。默认 `/var/lib/rustboard` 的
  祖先由 root 拥有，不受影响。
- **低风险**：`limit=0` 时 `record_failure` 不记录，`first_in_window` 恒 false，
  401 全为 DEBUG；`database` 在 data_dir 外时无告警，误配下 DB 可能落在共享目录。

## 4. 详细方案

### 4.1 KI-27：WS 会话级 per-IP 许可

#### 设计

新增一个仅持有生命周期、不改变语义的 guard：

```rust
#[derive(Clone)]
struct ConnectionGuards {
    _global: Arc<OwnedSemaphorePermit>,
    _per_ip: Arc<ConnectionPermit>,
}
```

- `serve_tls` 取得 `permit` 与 `connection` 后，把两者包成 `Arc` 放进
  `ConnectionGuards`；TLS service 的每个请求扩展插入 `guards.clone()`。
- `agent_ws` 增加 `Extension<ConnectionGuards>`，把 guards 移入 `on_upgrade` 的
  async 块，与现有 `_permit`（session_slots）一起持有到 `dispatch` 返回。
- 非 WS 的 HTTP 请求只持有到响应结束；WS 升级后由 upgrade future 持有，
  因此 `serve_connection` 提前返回不会释放 per-IP/全局连接许可。
- 不新增配置项；`max_connections` 和 `max_connections_per_ip` 的含义不变。
- 不在 `agent_ws` 内另取 per-IP 许可（避免与 TLS 许可双计数），除非扩展方案无法
  覆盖所有升级路径。

#### 测试

- 单测：`ConnectionGuards` 在 clone 后 permit 不释放，最后一个 guard drop 后释放
  （可用现有 `ConnectionLimiter` 计数/信号量 permits 断言）。
- e2e：小实例 `max_connections_per_ip=2`、`max_connections=8`，同一 IP 建立 2 条
  WS 成功，第 3 条被拒（503/连接关闭）；另一 IP 仍可连接；已有 agent 保持 online。
- 回归：正常 agent 多连接/控制发送/吊销清理、v034 多连接能力测试不变。

### 4.2 data_dir：目录 fd 化与 owner 校验

#### 4.2.1 路径规则（保留 v0.3.4 的静态规则）

保留 `normalize_private_dir_path`、共享/系统目录拒绝、sticky/相对路径拒绝。
新增/收紧：

- 从 `/` 逐组件打开目录，任何组件为符号链接立即拒绝；不再依赖“先 lstat 再按
  原始路径操作”。
- 祖先目录要求：
  - 非 root 进程：uid 必须等于 `geteuid()`；
  - root 进程：uid 必须为 0；
  - 例外：root 拥有的 sticky 目录（如 `/tmp`、`/var/tmp`）可作为**祖先**遍历，
    但不能作为最终 data_dir；
  - 祖先 mode 不得对 group/other 可写（root sticky 目录除外）。
- 最终 data_dir：
  - 必须由当前 euid 拥有（root 要求 root 拥有）；
  - 不得带 sticky 位；
  - 已存在且权限过宽时收紧到 `mode`；更严格的权限保持不放宽。
- `/var/lib/rustboard/hub|agent`、`/tmp/<root-or-self-owned-unique>`、
  `/opt/rustboard/data` 仍合法；`/tmp/<attacker-owned>`、`/var/log`、`/etc/...`
  拒绝。

#### 4.2.2 打开/创建流程

Linux（发布目标）用 `openat2`，与 `agent/control/logs.rs` 的用法一致：

1. `open("/", O_PATH|O_DIRECTORY|O_CLOEXEC)`；
2. 对每个**祖先**路径组件：
   - `openat2(parent_fd, component, O_PATH|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC,
     RESOLVE_BENEATH|RESOLVE_NO_MAGICLINKS|RESOLVE_NO_SYMLINKS)`；
   - `ENOENT` 时 `mkdirat(parent_fd, component, 0o700)` 后重新打开；
   - 其他错误（`ELOOP`/`ENOTDIR`/`EXDEV`/`EACCES`）上抛，不吞错；
3. 最终目录用 `O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC` 打开（`O_PATH` fd 不能
   `fchmod`，不能用于最终目录），对每个已打开目录 `fstat` 校验 uid/mode；
4. 最终目录若 group/other 位非 0，`fchmod(fd, 0o700)`；已合规不 chmod；
5. 目录创建与 chmod 全部基于 fd，路径被替换不会作用到新目标；
6. 关闭 fd；调用方后续仍用路径访问（DB/cert），但祖先已保证不可被非特权用户写，
   残留竞态仅限 root 自身或已获 root 权限的主体。

非 Linux：保留 v0.3.4 的 lstat 路径检查并在文档标注“完整 fd 保证仅 Linux”；
本项目发布目标是 Linux，不新增跨平台承诺。

#### 4.2.3 接入点

- `common/fsutil.rs`：`ensure_private_dir` / `harden_dir` 改为 fd 实现；
  保留 `validate_private_dir_path` 供配置早失败，但实际创建/收紧不再只依赖它。
- `hub/main.rs`：数据目录/证书目录继续走 `ensure_private_dir`；DB 仍在
  data_dir 下时用 `open_with_private_data_dir`。
- `agent/main.rs`：`prepare_data_dir` 不变接口，底层 fd 化。
- `HubConfig/AgentConfig::validate`：保留静态校验，错误信息不变；owner 检查在
  实际打开时做（配置校验阶段目录可能尚不存在）。
- SQLite 主库/WAL/SHM 0600 逻辑不变；数据库在 data_dir 外时只 WARN，不 chmod 父目录。

#### 4.2.4 测试

- 确定性 TOCTOU：打开/校验一个目录后，把路径替换为指向 victim 的符号链接；
  最终 chmod 只能作用原 fd/原目录，victim 模式不变（Linux）。
- 祖先符号链接、尾斜杠/`/.`/`//`、中间普通文件、dangling symlink 拒绝。
- 祖先 owner/可写性：root 下他人 0777 非 sticky 父目录拒绝；root-owned sticky
  `/tmp` 作为祖先允许、作为最终目录拒绝；最终目录 owner 非 euid 拒绝。
- 默认 `/var/lib/rustboard/hub|agent` 静态校验通过；`/tmp/<unique>` 创建 0700；
  已有 0755 收紧 0700、DB/WAL/SHM 0600 回归。
- 不 chmod 真实 `/tmp`、`/etc`、`/`。

### 4.3 两项低风险告警

1. **limit=0 首失败 WARN**：`log_auth_failure` 的采样判断改为
   `limit == 0 || first_in_window`；仅影响日志级别，不影响 401/429 行为。
   测试：limit=0 下 1 次错误 token 产生 1 条 WARN，后续不刷屏（可用日志 capture
   helper 或计数器；避免依赖全局 subscriber）。
2. **database 外置 WARN**：`open_storage` 在 DB 父目录不是 `data_dir` 时打一次
   `warn!`，点明“数据库不在 data_dir 下，父目录不做 0700 收紧；DB 文件仍 0600”。
   不拒绝启动。测试：用 helper 捕获日志或检查 `open_storage` 返回路径/日志标记；
   e2e 启动一次外置 DB，断言 WARN 出现且服务可用。

## 5. 接口、配置与兼容性

| 变更 | 兼容性 |
|---|---|
| WS TLS 许可持有到会话结束 | 无配置变化；`max_connections`/`per_ip` 上限恢复设计语义 |
| data_dir 目录 fd 化 | 行为收紧；默认路径不受影响；root 下 data_dir 必须 root 拥有，非 root 必须自己拥有 |
| data_dir 祖先不可被非特权用户写 | 行为收紧；`/tmp/<unique>` 仍可用；他人可写父目录下启动失败 |
| limit=0 首失败 WARN | 仅日志；不改变 401/429 |
| database 外置 WARN | 仅日志；不改变启动/权限 |
| 协议 / DB schema | 仍 v2 / v6，无变更 |
| 证书格式 | 不变 |

升级/回滚：

- v0.3.4 → v0.3.5 可直接滚动升级；无 DB 迁移、无协议/证书变更。
- 若现有部署把 data_dir 放在他人拥有的目录（例如 root 服务使用用户 home），
  v0.3.5 会拒绝启动；迁移到 root 拥有的专用目录，或改用服务用户运行。
- 回滚 v0.3.4 只回代码；目录权限已收紧不可逆但无害；KI-27 行为恢复旧逻辑。
- 所有修复用追加提交，不改写已推送历史。
